# agino-gpu 设计文档

版本：草案 1（2026-10-26；第 7 节按界面草案 3 简化）。决策来源：agino infra `docs/decisions.md` D-141。本文是实现和测试的依据；实现中发现与本文不符时，先改本文再改代码。

## 1. 目标与范围

在“集显 + 独显”的机器上，让用户按使用场景方便地选择和切换显卡：

- 日常：集显负责桌面，独显空闲时断电休眠；需要性能的应用自动或手动改用独显，不用注销。
- 省电：完全不用独显（集显模式）。
- 性能：所有程序由独显渲染（独显优先），或在有 MUX 的机型上让屏幕直接接到独显（独显直连）。

交付物：

| 组件 | 说明 |
|---|---|
| `agino-gpud` | 系统总线服务（root，按需由 D-Bus 激活，空闲退出），能力检测、模式读写、生成配置 |
| `agino-gpu-apply` | 开机时在显示管理器之前运行的一次性服务，把已保存的模式落实到本次启动 |
| `agino-gpu-run` | 命令行启动器（类似 `prime-run`），用独显运行任意命令；也是兼容配置的唯一实现 |
| `libagino-gpu` | 客户端库：D-Bus 封装、sysfs 只读状态、按应用规则、环境变量集合 |
| 快捷面板插件 | dde-tray-loader V2 插件：快捷面板里的两格“显卡”磁贴（与 Wi-Fi、蓝牙同类）和面板内的下级页面；不提供单独的任务栏托盘图标（D-141 补充） |
| 控制中心插件 | dde-control-center V25 插件，“显示”下的子页“显卡” |
| 补丁（infra 里的移植包） | dde-application-manager 认 `PrefersNonDefaultGPU`；dde-launchpad 和 dde-shell 任务栏的“使用独立显卡运行”右键菜单 |

范围：X11（Xorg + KWin X11，agino 当前的会话）。Wayland 只在接口上预留（模式名、D-Bus 接口不绑定 X11），不实现。

## 2. 支持的硬件形态

daemon 启动时分类，界面和可选模式都由分类决定。

| 形态 | 判定 | 提供的功能 |
|---|---|---|
| H1 混合笔记本 | 两块及以上 GPU，`boot_vga=1` 的是集显，屏幕（eDP）接在集显上 | 全部模式（独显直连除外） |
| H2 带 MUX 的混合笔记本 | H1 + 检测到 MUX 接口（第一期：`/sys/devices/platform/asus-nb-wmi/gpu_mux_mode`） | 全部模式 |
| H3 台式机 | 无内置屏幕（无 eDP/LVDS 连接器）；显示器接在哪块卡由连接器状态判断 | 显示器接集显：混合、集显、按应用规则；接独显：只显示状态和按应用规则（不提供集显模式） |
| H4 外接显卡坞（eGPU） | 独显的 PCI 路径经过 Thunderbolt（`/sys/bus/thunderbolt` 下的设备，或 `removable` 属性） | 混合 + 按应用规则；拔出时规则自动失效；不提供集显/独显优先（热插拔下不安全） |
| H0 单显卡 | 只有一块 GPU | 快捷面板磁贴和控制中心入口都不出现；`agino-gpu-run` 原样运行命令并提示 |

厂商：

| 厂商 | 驱动 | 按应用的方式 | 运行时休眠 |
|---|---|---|---|
| NVIDIA | 闭源 R580（开源内核模块） | PRIME 按需渲染：`__NV_PRIME_RENDER_OFFLOAD` 等（见 5.1） | RTD3，需要 `power/control=auto`（见 6.4） |
| AMD 独显 | amdgpu（Mesa） | `DRI_PRIME=pci-XXXX_XX_XX_X`，Vulkan 用 `MESA_VK_DEVICE_SELECT` | amdgpu 默认 runpm |
| Intel 独显（Arc） | i915/xe（Mesa） | 同 AMD | 驱动默认 |

AMD、Intel 独显、台式机、eGPU：先按本文实现，**有设备后再测**，在此之前测试记录标“未在真机验证”（D-141 第 7 条）。

## 3. 模式与状态机

### 3.1 模式

| 模式 ID | 中文名 | 渲染 | 独显状态 | 生效方式 |
|---|---|---|---|---|
| `hybrid` | 混合（默认） | 集显；按应用规则的应用用独显 | 空闲时休眠 | 默认状态 |
| `integrated` | 集显 | 只有集显 | 驱动不加载，设备从 PCI 移除（ASUS 另用 `dgpu_disable` 断电） | 重启 |
| `dedicated` | 独显优先 | 全部由独显渲染（反向 PRIME），集显只负责输出画面 | 一直工作 | 注销（X 服务器重启） |
| `mux-dedicated` | 独显直连 | 只有独显，屏幕直接接独显 | 一直工作 | 重启（固件开机时锁定） |

按应用规则不是模式，是 `hybrid` 下的功能；在 `dedicated` 和 `mux-dedicated` 下规则无意义（全都用独显），在 `integrated` 下规则被忽略，界面上标明。

`integrated` 选“重启”而不是“注销”：要可靠地卸载 nvidia 模块并移除设备，必须在 Xorg 和所有 GL/CUDA 进程启动前完成；注销后仍可能有用户服务占用设备，强行卸载有卡死风险（supergfxctl 的已知问题）。`dedicated` 只改 Xorg 配置，X 服务器重启即可，但 lightdm 注销后是否重启 X 服务器要在 157 上确认（第 11 节 V-1），不确认则同样降级为“重启”。

### 3.2 状态

daemon 维护三个量：

- `ConfiguredMode`：已保存的模式（`/etc/agino-gpu/mode`），下次启动/登录要用的。
- `ActiveMode`：本次启动实际生效的模式，由 `agino-gpu-apply` 在开机时写入 `/run/agino-gpu/state`，并在运行时根据实际情况校验（例如 `dedicated` 下 Xorg 的主 GPU 确实是独显）。
- `PendingAction`：`none` / `logout` / `reboot`，由 `ConfiguredMode` 与 `ActiveMode` 的差异推出。

```
            SetMode(m)                         开机 / 注销
 Active=a ───────────────► Configured=m ───────────────────► Active=m
   │                         Pending=logout|reboot             Pending=none
   │  SetMode(a)（改回）
   └──────────────────────► Configured=a, Pending=none（撤销，不需要注销/重启）
```

规则：

1. `SetMode` 只写配置，不在运行中拆卸驱动或改 X；所有落实都在下次开机或 X 服务器启动时完成。这样任何一步失败都不会把当前会话弄坏。
2. 从 `mux-dedicated` 或改到 `mux-dedicated`，`PendingAction` 一定是 `reboot`。
3. 不同时排队两种操作：已有待生效的模式时再次 `SetMode`，以最后一次为准。
4. 开机时落实失败（例如 `dedicated` 下 Xorg 起不来），`agino-gpu-apply` 回退到 `hybrid`，把失败原因写进 `/var/lib/agino-gpu/last-failure`，下次登录由快捷面板插件发桌面通知，磁贴副标题变红。
   - 实现细节（P1 审查后）：可能是暂时性的原因（设备晚出现、MUX 接口还没加载）只对本次开机回退，保存的模式不变，下次开机再试；确定不可行的（硬件不支持、固件 MUX 没切过去、集显没有接屏幕）永久改回 `hybrid`。集显模式下 udev 辅助程序遇到 MUX 处于直连、看不到集显、外接显卡坞时不移除独显；`agino-gpu-apply` 移除后若集显 10 秒内没有任何接上的屏幕，就删掉 modprobe 规则、写 `/run/agino-gpu/keep-dgpu`、重新扫描 PCI 并重放 `add` 事件，把独显找回来。

### 3.3 切换前检查（`SetMode` 返回错误或警告）

| 检查 | 适用 | 结果 |
|---|---|---|
| 有显示器接在独显的接口上（`/sys/class/drm/cardN-*/status` 为 `connected`，N 是独显） | 改到 `integrated` | 警告：这些显示器将不能用；需要 `force` 参数确认 |
| 内置屏幕只接在独显上（H2 已在直连状态） | 改到 `integrated` | 拒绝 |
| H3 显示器接在独显 | 改到 `integrated` | 拒绝 |
| H4 eGPU | 改到 `integrated`/`dedicated` | 拒绝 |
| 安全启动开启且 NVIDIA 模块未签名可用 | 改到 `dedicated`/`mux-dedicated` | 警告（独显驱动加载不了时屏幕可能黑） |
| 当前是电池供电 | 改到 `dedicated`/`mux-dedicated` | 只提示耗电 |

## 4. 各模式的落实

所有生成的文件头部写 `# Generated by agino-gpu; do not edit.`，daemon 只增删自己生成的文件。

### 4.1 hybrid

- 不生成 Xorg 配置：Xorg 会自动把独显加为副屏 GPU（157 实测 `NVIDIA(G0)`），按需渲染可用。
- 运行时休眠：见 6.4。
- 写 `/run/agino-gpu/offload.env`（按应用用独显的环境变量，见 5.1），供 DAM 补丁、右键菜单、`agino-gpu-run` 共用。只有 `ActiveMode=hybrid` 且有可用独显时这个文件才存在；右键菜单以它存在与否决定是否显示。

### 4.2 integrated

开机时（`agino-gpu-apply.service`，`Before=display-manager.service systemd-modules-load.service` 之后的位置见 6.1）：

- NVIDIA：`/etc/modprobe.d/agino-gpu-integrated.conf`：只写 `blacklist` 不够（按名字加载和依赖加载不受它限制），四个模块（nvidia、nvidia_drm、nvidia_modeset、nvidia_uvm）各写 `install <模块> /bin/false`，同时各写一行 `blacklist`：systemd-modules-load 应用 kmod 的黑名单，跳过这些模块而不报错；只有 `install` 时，`/etc/modules-load.d` 里列出的 nvidia_drm 让 systemd-modules-load.service 每次开机失败（157 实测，2026-10-27）。回退恢复独显后（`agino-gpu-apply` 的 restore），udev 只按设备加载 nvidia，apply 再重启一次 systemd-modules-load.service 加载 nvidia_drm 等（单元的失败状态也随之清除）；initramfs 里若带 nvidia 模块需要 `update-initramfs`（agino 的 initramfs 是否带 nvidia 要确认，V-2）。
- 把独显及其同一插槽的音频、USB-C 功能从 PCI 移除：`echo 1 > /sys/bus/pci/devices/<addr>/remove`（在驱动加载之前）。移除后设备进入 D3cold 由平台决定；功耗在 157 上实测（V-3）。
- ASUS：若有 `dgpu_disable`，在移除之后写 1（固件断电），改回其他模式时在开机早期写 0 并重新扫描 PCI（`/sys/bus/pci/rescan`）。驱动加载中绝不写 `dgpu_disable`。固件断电的独显在 coldplug 时仍会被枚举（D3cold），驱动探测失败（`Unable to change power state from D3cold to D0`），而重新扫描不会再探测已存在的设备；所以写 0 之后先移除可见的独显各功能再重新扫描，然后重启 systemd-modules-load.service（157 实测，2026-10-27）。
- AMD/Intel 独显：同样移除 PCI 设备（不需要 modprobe 规则，amdgpu 同时驱动集显时不能拉黑）。

### 4.3 dedicated（独显优先，反向 PRIME）

- 生成 `/etc/X11/xorg.conf.d/90-agino-gpu.conf`：

```
Section "OutputClass"
    Identifier "agino-gpu dedicated"
    MatchDriver "nvidia-drm"          # AMD/Intel 独显：MatchDriver "amdgpu"/"i915"，并用 PCI 匹配区分集显
    Driver "nvidia"
    Option "PrimaryGPU" "yes"
    ModulePath "/usr/lib/nvidia/xorg"
    ModulePath "/usr/lib/xorg/modules"
EndSection
```

- lightdm `display-setup-script`（`/etc/lightdm/lightdm.conf.d/90-agino-gpu.conf` 指向 `/usr/libexec/agino-gpu/display-setup`，agino 目前没有占用这个钩子）：`xrandr --setprovideroutputsource modesetting NVIDIA-0; xrandr --auto`，让内置屏幕（接在集显上）显示独显渲染的画面。只在 `ActiveMode=dedicated` 时执行，其他模式直接退出。
- 风险：dde-daemon 的显示服务（display1）对 provider 的处理、KWin X11 的合成在反向 PRIME 下的表现（撕裂、刷新率），在 157 上测（V-4）。

### 4.4 mux-dedicated（独显直连）

- 后端接口 `MuxBackend`（能力检测、读取当前位置、写入目标位置）。第一期实现 `AsusWmiMux`：`/sys/devices/platform/asus-nb-wmi/gpu_mux_mode`，0 = 独显直连，1 = 混合；写入后固件在下次开机生效。**读回的是本次开机的位置，不是已写入、待下次开机的位置**（157 实测 2026-10-27：开机为 0 时写 1，读回仍是 0），所以 SetMode 每次都写目标位置、回滚按原模式推算，不能"读出来比较、相同就不写"（否则同一次开机里 混合 → 直连 → 混合 会停在直连）。内核提示 `/sys/devices/platform/asus-nb-wmi` 下的属性已弃用、将改到 `/sys/class/firmware_attributes`（asus-armoury），后续要跟进。
- 其他厂商（Lenovo、MSI 等）没有主线内核接口，不实现，留接口。
- 直连状态下集显不可见，Xorg 只有独显；daemon 报告 `ActiveMode=mux-dedicated`，界面只提供“改回混合（需重启）”。

## 5. 按应用使用独显

### 5.1 环境变量集合（唯一来源：`libagino-gpu` 的 `offloadEnvironment(gpu)`）

NVIDIA：

```
__NV_PRIME_RENDER_OFFLOAD=1
__NV_PRIME_RENDER_OFFLOAD_PROVIDER=NVIDIA-G0     # 多块 NVIDIA 时指定；单块时省略
__GLX_VENDOR_LIBRARY_NAME=nvidia
__EGL_VENDOR_LIBRARY_FILENAMES=/usr/share/glvnd/egl_vendor.d/10_nvidia.json
__VK_LAYER_NV_optimus=NVIDIA_only
QT_FFMPEG_DECODING_HW_DEVICE_TYPES=cuda,vaapi
QT_FFMPEG_ENCODING_HW_DEVICE_TYPES=cuda,vaapi
```

Qt 多媒体的 FFmpeg 后端启动时探测 CUDA，加载 `libcuda` 会打开 `/dev/nvidia*`、唤醒休眠的独显，混合模式下控制中心、音乐等任何用 Qt 多媒体的程序一启动独显就醒（2026-10-26 在 105 上实测：控制中心停在“个性化”页独显也从 suspended 变 active；设成只用 VA-API 后保持 suspended）。所以 `/etc/X11/Xsession.d/68agino-gpu` 在 `offload.env` 里有 `__NV_PRIME_RENDER_OFFLOAD` 时（混合模式、独显是 NVIDIA）给整个会话设 `QT_FFMPEG_DECODING_HW_DEVICE_TYPES=vaapi` 和 `QT_FFMPEG_ENCODING_HW_DEVICE_TYPES=vaapi`（用户自己设过的不改；dde-session 会把 Xsession 的环境带进 systemd 用户实例），用独显的应用由上面两行恢复 CUDA（D-145）。独显优先、独显直连、集显、单显卡的机器都不设。

`__EGL_VENDOR_LIBRARY_FILENAMES` 是为 Chromium/Electron（X11 上走 EGL/ANGLE）加的，NVIDIA EGL 在 X11 按需渲染下是否正常要在 157 上验证（V-5）；不正常就只对 Chromium 类应用改走 Vulkan（见 5.4）。

Mesa 独显（AMD/Intel）：

```
DRI_PRIME=pci-0000_03_00_0            # 用 PCI 地址，避免多块卡时 DRI_PRIME=1 选错
MESA_VK_DEVICE_SELECT=1002:73df       # vendor:device，配合 Mesa 的 device-select 层
```

不设置 `VK_ICD_FILENAMES`/`VK_DRIVER_FILES`（会让 32/64 位和 Flatpak 内路径不一致）。视频解码（VA-API/VDPAU）不改，留在集显上，省电。

### 5.2 规则存储

- 规则是用户级的：用户 DConfig `org.agino.gpu`（appid `agino-gpu`，定义文件 `data/dconfig/org.agino.gpu.json`），键 `rules` 存一个 JSON（`rules.h` 的 `RuleSet`：`{"version":1,"apps":[{"appId":"steam"}],"paths":[{"path":"…","launcherEntry":"agino-gpu-<hash>.desktop"}],"pauseOnBattery":true}`）。两种规则：
  - 按应用（`apps`）：来自系统里的应用（DAM 的应用列表），或用户浏览选中的 `.desktop` 文件（应用标识取文件名去掉 `.desktop`）。
  - 按文件（`paths`）：来自控制中心“选择文件…”选中的可执行文件、AppImage 或脚本（D-141 补充：允许用户浏览文件指定应用，不只读系统已安装的应用）。路径存规范化后的绝对路径；文件被移动或删除时规则在界面上标“文件不存在”，不自动删除。
  - 同一 DConfig 的其他键由客户端库维护（P2 实现）：`effectivePaths`（此刻生效的按文件规则路径；不在混合模式或因电池暂停时为空，DAM 补丁只读这个键，不解析 JSON、不判断电源），`appliedApps` / `appliedEnvironment`（哪些应用的 DAM 配置里有我们写的项、写的是哪些，用于之后准确删除），`dismissedFailure`（用户已关闭的切换失败通知）。
- 规则落到 DAM：对每个 `gpu=discrete` 的应用，把 5.1 的变量写进 DAM 的 DConfig `org.deepin.dde.application-manager` 子路径 `/<appid>` 的 `appExtraEnvironments`，并在同一列表里加一个标记项 `AGINO_GPU_RULE=<我们实际加入的变量名，逗号分隔>`；用户自己已设置的同名变量保留、我们的跳过且不进标记，删除规则时只删除标记列出、且值与我们写入的一致的项（P2 审查修正：原来的 `AGINO_GPU_RULE=1` 会把用户自己的同值变量一起删掉）。
- 按文件的规则不写 DAM 的按应用配置（没有应用标识），由 DAM 补丁在启动时匹配（5.3 第 1 条）。用户勾选“在启动器里创建入口”时，在 `~/.local/share/applications/` 写一个 `agino-gpu-<路径哈希>.desktop`（`Exec` 指向该文件，`Name` 默认取文件名、可改），删除规则时一并删除；入口只是方便启动，规则本身靠路径匹配生效。
- 电池策略：一个整组开关 `pauseOnBattery`（布尔，默认开），不按条设置（草案 3 简化）。开着时，切到电池供电由客户端库（`DamRuleSync`，电源状态取自 UPower 的 `OnBattery`）把所有规则项从 DAM 里拿掉并清空 `effectivePaths`，接上电源后恢复。执行者是快捷面板插件（随 dde-tray-loader 在登录时加载并常驻，不需要用户打开面板）；控制中心插件打开时也运行同一个同步，使改动不依赖快捷面板立即生效（同步是幂等的）；插件被禁用时电池策略不生效（在本文记录，界面上不另加说明）。
- 内置推荐规则（`/usr/share/agino-gpu/default-rules.json`，例如 Steam、Blender、DaVinci Resolve），用户可关。第一期默认不启用任何规则，只在界面上作为“推荐”列出。

### 5.3 三个入口

### 5.4 应用兼容（D-141 第 8 条）

P4 只做内置识别，不做通用的 profiles/*.json 配置机制；不改应用自己的文件。Chromium 类应用在带 `__NV_PRIME_RENDER_OFFLOAD=1` 时需要 ANGLE-Vulkan 启动参数（5.4.1），**只有一份实现：`agino-gpu-run`（`src/lib/chromium.cpp` + `src/run`）**。DAM 补丁在最终环境含 `__NV_PRIME_RENDER_OFFLOAD=1` 时改为执行 `/usr/bin/agino-gpu-run -- PROGRAM ARGS`（供启动器/任务栏菜单和始终用独显规则，见 5.3 第 1、2 项）；Exec 以 `env` 开头时按 GNU env 的规则找到真正的程序（选项、`-S` 字符串、嵌套 env，infra D-148 补充），Exec 自己去掉该变量或设成 1 以外的值时不包装，并从启动环境里去掉 offload.env 中它自己没设的其他变量（只剩这些变量时 GLX/EGL 和 Vulkan 都只认 NVIDIA，程序没有可用的 GPU，Chromium 会整体禁用 GPU；DAM 1.2.59.6）。`agino-gpu-run` 只补环境里缺少的变量（已有同名变量优先，`env -i` 清掉的由它补回），Chromium 参数只在最终环境 `__NV_PRIME_RENDER_OFFLOAD=1` 时加；Debian 的 `/etc/chromium.d/zz-agino-gpu`（包装脚本按文件名顺序读取，`zz-` 保证最后执行、看到完整的 `CHROMIUM_FLAGS`）同样交给 `agino-gpu-run --chromium -- /usr/bin/chromium …`。Flatpak 不在 P4 范围（用户决定 2026-10-26）。

#### 5.4.1 Chromium 在 X11 按需渲染下失败的根因（2026-10-26 调查）

环境：105（Intel Arrow Lake 集显驱动屏幕 + RTX 5080 Laptop，驱动 580.178.04，`modesetting` + `NVIDIA-G0` 两个 provider），Debian Chromium 156.0.8078.47（ANGLE `3b89d84e`），deepin kwin X11 合成器开启。带 5.1 的变量启动。

因果链（源码行号对应 Chromium tag 156.0.8078.47 与其 DEPS 固定的 ANGLE 版本）：

1. Chromium 的 GPU 进程初始化 ANGLE 时总带上 `EGL_X11_VISUAL_ID_ANGLE`（`ui/base/x/x11_gl_egl_utility.cc:43-58`）。visual 由 `VisualManager::ChooseVisualForWindow(want_argb=true)` 选：有合成器（`_NET_WM_CM_S0` 有主人）就用 32 位 ARGB visual（`ui/gfx/x/visual_manager.cc:85-98`）。候选列表来自 X 协议请求 `glx().GetVisualConfigs`（`ui/gfx/x/visual_picker_glx.cc:195-203`），由 X 服务器（Intel 一侧）回答，不经过 libGL。105 上选中的是 0x6b9（depth 32）。
2. ANGLE 的 GLX 后端用 libGL（按需渲染时 glvnd 选 NVIDIA）的 `glXChooseFBConfig` 列出全部 fbconfig，找 `GLX_VISUAL_ID` 恰好等于请求值的那个，找不到就返回 `EGL_NOT_INITIALIZED`「Invalid visual ID requested」，没有退路（`src/libANGLE/renderer/gl/glx/DisplayGLX.cpp:166-190`）。
3. NVIDIA 在按需渲染下只给 12 个 visual（0x21、0x22、0x57a–0x57e、0x619–0x61d），全是 depth 24，没有任何 32 位；同一屏幕上 Mesa 给 336 个（`glxinfo -v` 对照，X 服务器共 337 个 visual）。0x6b9 不在其中 → GPU 进程初始化失败 → 全部软件渲染。

因果验证：暂停 kwin 合成后，Chromium 窗口改用 0x21（depth 24），同样的变量和默认 `--use-angle=gl` 即得到 `ANGLE (NVIDIA …, OpenGL 4.5.0 NVIDIA 580.178.04)`，各项加速 enabled；恢复合成后又失败。

各后端在合成器开启时的结果（数据来自 Chromium 自己的 `SystemInfo.getInfo`，经 DevTools 协议读取，`tests/manual/chromium-gpu-probe`）：

| 配置 | 渲染器 | gpu_compositing | webgl | vulkan |
|---|---|---|---|---|
| 不带变量（集显基线） | Intel Mesa | enabled | enabled | disabled_off |
| 变量 + `--use-angle=gl`（默认） | 无（初始化失败） | disabled_software | disabled_off | disabled_off |
| 变量 + `--use-angle=gl-egl` | NVIDIA OpenGL ES 3.2 | **disabled_software** | enabled_readback | disabled_off |
| 变量 + `--use-angle=vulkan` + 三个 feature | NVIDIA Vulkan 1.4.312 | enabled | enabled | enabled_on |
| 同上，但后面再跟一个 `--enable-features=WebRTCPipeWireCapturer` | NVIDIA Vulkan | **disabled_software** | enabled_readback | **disabled_off** |

结论：

- 根治在上游，我们单方面做不了：Chromium 应在 ARGB visual 不被 libGL 的 fbconfig 支持时退回不透明 visual，或 ANGLE 按深度/类别退而求其次；NVIDIA 可在按需渲染下提供 32 位 visual。报告草稿见 `docs/upstream-reports.md`，由用户提交（用户决定 2026-10-26）。给 Debian chromium 打补丁要分叉并构建整个 Chromium，且不覆盖 Chrome/Electron，不做。
- 过渡方案只能是 ANGLE Vulkan：gl-egl 能用 NVIDIA 但合成退回软件。
- 开关语义：`base::CommandLine` 对重复开关取最后一个（`base/command_line.cc:436-455`），`FeatureList` 只读一个 `--enable-features` 和一个 `--disable-features`，disable 优先（`base/feature_list.cc:420-460`）；Electron 相同。所以 feature 必须并入应用自己的 `--enable-features`（最后一个），不能另加一个；用户 `--disable-features` 里禁用了这三个 feature 之一、或已给 `--use-angle=` 时不改。
- 上游现状：没有修复，也没有维护者给出根因；NVIDIA 论坛自 2020 年起（Chrome 86–139、驱动 435–535）有同样报错的用户报告，GNOME/KDE 的 switcheroo-control 只设变量，X11 上同样失败。`DefaultANGLEVulkan` 在 156 默认关闭，Google 只以实验方式对部分用户开启。

#### 5.4.2 验收（2026-10-27，105 真机，Debian chromium 156.0.8078.47，屏幕 2560×1600 240 Hz，KWin 合成开）

Chromium 升级后按同样方法重跑（`tests/manual/`，均需在用户的 X 会话里运行）。

- **WebGL 一致性测试**（`chromium-webgl-cts`，Khronos 当前版本，WebGL 2）：10 个目录 conformance/{context,canvas,rendering,textures/misc,extensions,reading,misc}、conformance2/{context,rendering,textures/misc}，每边 276 个测试页。集显基线（不带变量）失败 2 页（`conformance2/textures/misc/immutable-tex-render-feedback.html` 48 个子项、`conformance/extensions/khr-parallel-shader-compile.html` 2 个子项）；经 `agino-gpu-run` 在 NVIDIA Vulkan 上失败 1 页（同一个 `immutable-tex-render-feedback.html`，48 个子项）。没有新增失败，两边都没有超时，日志里没有 GPU 进程问题。
- **稳定性**（`chromium-stability`，1080p60 H.264 循环播放，旁边一个不限帧率的 WebGL 2 分形）：经 `agino-gpu-run` 跑 600 秒，GPU 进程 0 次重启，WebGL 166.7 fps，视频解码为软件 `FFmpegVideoDecoder`（Debian chromium 默认不用 VA-API），关闭后 10 秒独显回到 suspended。
- **已知限制：独显路径的显示吞吐**。上面的满负荷场景里视频掉帧 26%（9237/35212），集显基线 300 秒只掉 0.4%（72/17979，WebGL 198.8 fps）。只播视频时两边都几乎不掉帧（独显 6/7200，集显 1/7209，各 120 秒）。所以掉帧来自不限帧率的渲染把按需渲染的显示通道（独显画面复制到集显后显示）占满，不是 GPU 进程的问题，参数也改不了它（gl-egl 连合成都退回软件）。此判断没有单独验证；日常网页在这种情况下是否受影响也没有测。

### 6.4 运行时休眠（前置任务，在 infra 里做，D-141 第 6 条）

- 现状（kernel-graphics-hardware.md 10.16）：tlp 由 deepin-power-control 的模板把 `RUNTIME_PM_ON_AC/BAT` 写死为 `on`；手动打开后独显每分钟被唤醒 18～22 秒，电池多耗 7～8 W。
- 前置任务要做到：(1) tlp 不再强制 NVIDIA 设备为 `on`（改 deepin-power-control 模板或用 `RUNTIME_PM_DENYLIST` 之外的方式，在 infra 决定）；(2) 找出并消除反复唤醒的来源；(3) 157 电池实测：休眠时功耗低于强制唤醒。
- 已完成（infra D-143，agino-kernel-config 26.0.13）：`/etc/tlp.d/41-agino-dgpu-rtd3.conf` 让 tlp 跳过 `nvidia amdgpu snd_hda_intel pcieport`（这些驱动自己打开运行时 PM），`/usr/lib/udev/rules.d/80-agino-dgpu-rtd3.rules` 给 NVIDIA 显卡和它的 HDMI 音频设 `auto`。独显、音频、上游根端口一起挂起，独显进入 D3cold。157 接电源时整机 32.7 W → 22.1～22.6 W；独显断电时显存内容存进内存，多占约 440 MiB。
- agino-gpu 不再带自己的 udev 规则，也不在运行中改 tlp；只读这些设备的状态。Intel 独显（i915/xe 同时驱动集显，不能整体跳过）在 P6 有设备时再处理。

### 6.5 不唤醒独显

快捷面板插件和控制中心只读：`/sys/bus/pci/devices/<addr>/power/runtime_status`、`power/runtime_suspended_time`、`/sys/class/drm/card*/status`、`/proc/*/fd` 的链接目标（判断谁打开了 `/dev/nvidia*` 或独显的 `renderD*`）。禁止调用 `nvidia-smi`、`xrandr --listproviders`、`vulkaninfo`、`glxinfo`、打开独显设备节点。轮询：只在快捷面板打开时进行（磁贴每 10 秒、下级页面打开时每 2 秒），面板关闭时不轮询；`runtime_status` 变化没有 uevent，只能轮询，读一个 sysfs 文件的代价可以忽略。

### 7.1 快捷面板插件（dde-tray-loader 2.0.38，`PluginsItemInterfaceV2`）

- 接口：`interfaces/pluginsiteminterface_v2.h`，IID `com.deepin.dock.PluginsItemInterface_V2`；`flags()` 为 `Dock::Type_Quick | Dock::Quick_Panel_Multi`（两格，与 Wi-Fi、蓝牙同类），不带 `Attribute_CanInsert`（不能拖到任务栏托盘区，按用户要求不提供托盘图标）；元数据 `{"api":"2.0.0","depends-daemon-dbus-service":""}`；安装到 `/usr/lib/dde-dock/plugins/`；`itemWidget()` 只对 `Dock::QUICK_ITEM_KEY` 返回磁贴，对自己的项键返回空：dde-tray-loader 2.0.38 只在项键有控件时才建托盘项（`WidgetPlugin::itemAdded`），P2 曾返回一个空白占位控件，结果托盘区多出一个空白图标、点开是切换弹窗（2026-10-26 用户在 105 上发现，已去掉）；下级页面靠 `itemPopupApplet(项键)` + `requestSetAppletVisible(项键, true)` 弹出（dde-shell 按 pluginId 匹配，不需要托盘项），关闭面板用 `requestSetAppletVisible(QUICK_ITEM_KEY, false)`（tray-loader 经该键控件所在窗口发 `closeQuickPanel`）；模板参照 `plugins/dde-dock/eye-comfort-mode/`。构建用 dde-tray-loader-dev 的 CMake 包 `DdeTrayLoader`（树内插件链接的 `dockpluginmanager-interface` 不在 dev 包里，树外只用头文件，第一步先验证能否编过，V-8）。
- 磁贴：只在多显卡时出现。左侧圆形图标表示当前模式；标题“显卡”；副标题只写当前模式名（“混合”），待生效时黄色“待重启”/“待注销”，上次切换失败时红色“切换失败”；独显是否工作在下级页面看。整块磁贴点击进入下级页面，不做“一点就开关”。
- 下级页面（面板内展开，与 Wi-Fi 列表相同的方式：`itemPopupApplet(QUICK_ITEM_KEY)` 返回页面控件，点击磁贴时 `requestSetAppletVisible(..., true)`；按 eye-comfort-mode 的写法实现，V-10 验证）：顶部“‹ 显卡”标题栏由 dde-shell 画（标题取 `pluginDisplayName`，插件不再自己画），页面第一行“独立显卡”和独显状态（休眠/工作中/已关闭）；最多一条提示条（“重启后切换到集显”［撤销］［立即重启］、“HDMI-1 接在独显上，集显模式下不可用”、“切换到独显优先失败，已恢复为混合”［详情］、“Flatpak 缺少 NVIDIA 运行时”［安装］）；模式单选只有模式名，未选中的项右侧标生效代价（“需重启”“需注销”），不写模式说明；正在使用独显的应用（为空时整组不显示）；底部“显卡设置”跳转控制中心。
- 快捷面板白名单：dde-shell 2.0.52 的快捷面板只显示 DConfig `org.deepin.dde.shell` / `org.deepin.ds.dock.tray` 的只读键 `quickPlugins` 里列出的插件（`QuickPanelProxyModel::filterAcceptsRow`；键说明里“未列出的放最后”已与代码不符）。本包装 override `/usr/share/dsg/configs/overrides/org.deepin.dde.shell/org.deepin.ds.dock.tray/50-agino-gpu.json`，在默认列表的连接类磁贴（network、bluetooth、wireless-casting）之后插入 `agino-gpu`；整表替换，dde-shell 改默认列表时要同步。安装后由 dde-dconfig-daemon 的 dpkg 触发器重载，任务栏重启（或重新登录）后生效。（2026-10-26 在 105 实测）
- 系统通知：插件加载时若有 `/var/lib/agino-gpu/last-failure`，发一次桌面通知：标题“显卡模式切换失败”，正文“已恢复为混合”，按钮“详情”；通知关闭后不再提醒。
- 注销、重启：`org.deepin.dde.SessionManager1` 的注销与 `RequestReboot`（agino 现有代码已在用）。

### 7.2 控制中心插件（dde-control-center 6.1.103，V25）

- 接口：`include/dccfactory.h`（`dccV25::DccFactory`，IID `org.deepin.dde.dcc-factory/v1.0`，宏 `DCC_FACTORY_CLASS`）；入口 `Gpu.qml` 根对象 `DccObject { name: "gpu"; parentName: "display"; weight: 120 }`（“显示”自己的子项权重 10～110）；安装用 `dcc_install_plugin(NAME gpu TARGET ...)` 到 `plugins_v1.1/gpu/`；`find_package(DdeControlCenter)`；模板参照 `examples/plugin-example/`。
- 内容（自上而下，分组不加副标题）：提示条（与快捷面板相同，只在有问题时出现，兼容问题如 Flatpak 运行时、Steam i386 库也在这里出现）；显卡列表（名称、“驱动 · 接的显示器”一行、独显状态）；“模式”四张卡片（模式名 + 一句短说明：按需使用独显 / 最省电 / 全部由独显渲染 / 性能最佳；未选中的标生效代价）；“使用独显的应用”（规则列表，按文件的规则多一行目录；每行只有移除按钮；末尾“添加 ›”和整组开关“使用电池时暂停”；非混合模式时整组变灰并标“仅混合模式”）。不设“高级”组（运行时休眠状态、命令行写在文档和 `agino-gpu-run --help` 里）。
- “添加应用”是“显卡”页的下级页面（`DccObject` 子页，路径“显示 › 显卡 › 添加应用”），不弹对话框（D-141 补充）。内容：搜索框和系统里的应用（DAM 列表，多选，已添加的显示为已勾选且不可改）；“其他程序”组，标题旁一句“从启动器启动时生效”，一行“选择文件…”打开 DTK 文件选择窗口（可选可执行文件、AppImage、脚本、`.desktop`），选中后显示文件名和目录，下面“添加到启动器”开关（默认开）；底部“取消 / 添加（N）”，添加后返回“显卡”页。
- 只在 `HardwareClass` 不是 `single` 时出现（`DccObject.visible` 绑定）。

### 7.3 文字

原则：布局能说明的不加说明文字，只留最关键的一句并尽量短；状态用颜色和位置表达，不重复写“当前”“已选”之类的标签。界面文字中英文，翻译走 Qt Linguist（控制中心插件用 `dcc_handle_plugin_translation`）。模式名固定为：混合、集显、独显优先、独显直连；按应用菜单固定为“使用独立显卡运行”。

## 8. 仓库与打包

```
agino-gpu/
├── CMakeLists.txt
├── src/lib/                 # libagino-gpu（检测、sysfs、环境变量、规则数据、D-Bus 线路类型）
├── src/client/              # libagino-gpu-client（两个插件共用：状态、D-Bus 调用、规则存储、DAM 同步、电源、界面文字）
├── src/daemon/              # agino-gpud、agino-gpu-apply、display-setup、integrated-remove
├── src/run/                 # agino-gpu-run
├── src/quickpanel/          # 快捷面板插件
├── src/dcc/                 # 控制中心插件（C++ + QML）
├── data/                    # D-Bus/polkit/systemd/udev/lightdm 文件、chromium.d/zz-agino-gpu、default-rules
├── tests/                   # 单元测试 + sysfs 夹具
└── docs/
```

- C++17（与 Qt 6.8 和 DTK 一致），Qt6 Core/DBus（daemon 不链接 Gui），插件用 DTK6 Widget / Qt Quick。
- `libagino-gpu` 是静态库（位置无关代码），链接进 daemon、工具和两个插件，不安装、没有公开 ABI。`libagino-gpu-client` 同样是静态库，只给两个插件用，另外链接 DTK Core（DConfig）；两个插件共用的界面文字在其中（翻译上下文 `AginoGpu`，安装到 `/usr/share/agino-gpu/translations/`）。polkit 授权直接调用 `org.freedesktop.PolicyKit1` 的 D-Bus 接口，不依赖 polkit-qt。
- 一个二进制包 `agino-gpu`（daemon、apply、run、库、系统文件、快捷面板插件、控制中心插件），直接依赖 dde-tray-loader、dde-control-center、dde-application-manager 等 DDE 组件：它只为 agino 而做，不拆“通用服务 + DDE 插件”（D-141 补充）。agino-desktop-dde 加 Recommends。
- 打包按 D-42：本仓库打标签（无 `v` 前缀），infra 加 `packages/agino-gpu/seed.json`。DAM、dde-launchpad、dde-shell 的补丁放 infra 各自的移植包，提版本。

## 9. 测试

### 9.1 单元测试（不需要硬件）

- 库里所有绝对路径（/sys、/proc、/etc、/run、/var）都经过 `AginoGpu::Root`，前缀取环境变量 `AGINO_GPU_ROOT`（空 = 真实文件系统），用夹具测试：157 的真实快照、AMD 独显笔记本、台式机（显示器分别接集显/独显）、eGPU、单显卡。夹具从真机采集（采集脚本 `tests/collect-sysfs.sh` 只读、不唤醒独显）；无设备的形态先按内核文档手写，标“合成”。
- 状态机、配置生成（逐字节对照期望文件）、规则写入 DAM（用 DConfig 的测试后端）、环境变量集合、兼容配置匹配。

### 9.2 虚拟机（build 上）

- 单显卡虚拟机：快捷面板磁贴和控制中心入口不出现，`agino-gpu-run` 正常透传。
- 补丁：启动器/任务栏菜单项在 `offload.env` 不存在时不出现；用伪造的 `offload.env` 验证 `dde-am --env` 确实把变量传给了应用进程（读 `/proc/<pid>/environ`）。

### 9.3 真机（157：Arrow Lake 集显 + RTX 5080，可能有 MUX）

每种模式：切换 → 注销/重启 → 检查 `ActiveMode`、Xorg 日志、`journalctl -b -p err`、桌面可用；按应用：glxgears/vkcube/Chromium/Electron/Steam 游戏/Flatpak 应用的渲染设备；电池功耗（方法沿用 10.16）；外接显示器插在独显接口时的提示。

### 9.4 待验证项（实现中逐项确认，结果写回本文）

| 编号 | 内容 | 影响 |
|---|---|---|
| V-1 | lightdm 注销后是否重启 X 服务器 | `dedicated` 是“注销”还是“重启”生效 |
| V-2 | agino 的 initramfs 是否带 nvidia 模块 | 分析（2026-10-26）：不需要 `update-initramfs`。initramfs 里旧的 modprobe 配置最多让 nvidia 在 initramfs 阶段加载不了，切到真实根文件系统后照常加载；反过来若 nvidia 已在 initramfs 里加载，移除 PCI 设备时内核先解绑驱动。仍要在 157 上用 `lsinitramfs` 核实 |
| V-3 | 157 移除 PCI 设备 / `dgpu_disable` 后的功耗 | `integrated` 的实际价值 |
| V-4 | 反向 PRIME 下 dde-daemon 显示服务和 KWin 的表现 | `dedicated` 可用性 |
| V-5 | NVIDIA EGL 在 X11 按需渲染下是否正常 | 2026-10-26 在 105（RTX 5080，驱动 580.178.04，Chromium 156）上测：`eglinfo -p x11` 带 5.1 的变量时 EGL 厂商为 NVIDIA、渲染器 RTX 5080，Firefox（EGL）P2 已实测在独显上；**Chromium 默认的 ANGLE-GL 失败**（`ANGLE Display::initialize error 12289: Invalid visual ID requested`，GPU 进程反复退出后整页软件渲染，独显照样被唤醒）。加 `--use-angle=vulkan --enable-features=Vulkan,VulkanFromANGLE,DefaultANGLEVulkan` 后正常（`GL_RENDERER = ANGLE (NVIDIA, Vulkan 1.4.312 (NVIDIA GeForce RTX 5080 …))`，各项硬件加速）；只加 `--use-angle=vulkan` 不够。Debian 的 `/usr/bin/chromium` 开头把 `CHROMIUM_FLAGS` 置空，环境变量传不进去，只能经 `/etc/chromium.d/` 片段或命令行参数。Vulkan：带变量时 NVIDIA 排第一，但 `__VK_LAYER_NV_optimus=NVIDIA_only` 没有隐藏集显和 llvmpipe |
| V-6 | `flatpak run` 是否把这些变量带进沙箱 | Flatpak 方案 |
| V-7 | agino 源里 NVIDIA 用户态库有没有 i386 | 没有：aginoos-unstable 和 milkyway 只发布 `all amd64 source`（2026-10-26）。用户指出 Steam 有原生 64 位测试版，不需要 i386 即可安装运行 |
| V-8 | 快捷面板插件能否只靠 dde-tray-loader-dev 树外编译 | 构建方式 |
| V-10 | 两格磁贴点击后在面板内展开下级页面的接口（`itemPopupApplet` + `requestSetAppletVisible`）在 dde-shell 2.0.52 上的行为 | 快捷面板下级页面 |
| V-11 | DAM 补丁按 `Exec` 程序路径匹配的可靠性（带参数、`env` 前缀、AppImage、脚本解释器） | 按文件的规则 |
| V-9 | 157 是否有 `gpu_mux_mode`，切换后重启的实际流程 | `mux-dedicated` |
| V-12 | 读 DRM 接口的 `status` 会不会唤醒挂起的独显 | 已确认不会：内核 `drm_sysfs.c` 的 `status_show` 只读缓存值（`READ_ONCE(connector->status)`，7.3 源码，2026-10-26） |
| V-13 | agino 装好的系统里 lightdm 是否已有别的 `display-setup-script`（deepin 25 的 lastore 用 `90-deepin-upgrade.conf` 占用；agino 不装 lastore） | 有则 `display-setup` 要串联调用原脚本，而不是覆盖 |
